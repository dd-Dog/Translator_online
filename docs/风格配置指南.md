# 翻译风格配置指南

## 概述

系统支持9种预定义翻译风格，可根据不同场景选择合适的风格，实现风格化翻译。

## 支持的风格

### 1. 通用风格 (general) ⭐ 默认

**适用场景**: 一般场景的标准翻译

**特点**:
- 忠实原文，准确传达意思
- 表达清晰，符合目标语言习惯
- 用词适中，不过于正式或口语化

**参数**: temperature=0.3

**示例**:
```
原文: Machine learning is a subset of AI.
通用风格: 机器学习是人工智能的一个子集。
```

---

### 2. 地道风格 (native) ⭐⭐⭐

**适用场景**: 追求自然地道的本地化表达

**特点**:
- 使用地道的本地表达方式
- 避免翻译腔，追求自然流畅
- 可以适当意译，但保持核心意思
- 使用目标语言的常用表达和俗语

**参数**: temperature=0.4

**示例**:
```
原文: It's raining cats and dogs.
直译: 正在下猫和狗。❌
地道风格: 下着倾盆大雨。✅
```

---

### 3. 商务风格 (business) 💼

**适用场景**: 商业文档、合同、报告等

**特点**:
- 使用正式、专业的商务用语
- 术语准确，符合行业规范
- 表达严谨，避免歧义
- 保持客观、中立的语气

**参数**: temperature=0.2

**专业术语**:
- company → 公司/企业
- contract → 合同
- revenue → 营收/收益
- stakeholder → 利益相关方

**示例**:
```
原文: The company will announce its quarterly earnings.
商务风格: 该公司将公布其季度财务业绩。
```

---

### 4. 学术风格 (academic) 🎓

**适用场景**: 学术论文、研究报告等

**特点**:
- 使用学术规范用语
- 专业术语准确，统一
- 表达严谨，逻辑清晰
- 保持客观、学术的语气
- 避免口语化表达

**参数**: temperature=0.2

**专业术语**:
- research → 研究
- hypothesis → 假设
- methodology → 方法论
- conclusion → 结论

**示例**:
```
原文: This study examines the impact of neural networks.
学术风格: 本研究考察了神经网络的影响。
```

---

### 5. 技术文档风格 (technical) 💻

**适用场景**: 技术文档、API文档、说明书等

**特点**:
- 技术术语统一且准确
- 表达简洁明确
- 使用祈使句和陈述句
- 保留代码、命令等技术内容不翻译

**参数**: temperature=0.2

**保留不翻译**:
- 代码块
- 命令行
- API名称
- 变量名

**示例**:
```
原文: Run the command `npm install` to install dependencies.
技术文档风格: 运行 `npm install` 命令以安装依赖项。
```

---

### 6. 文学风格 (literary) 📚

**适用场景**: 文学作品、小说、诗歌等

**特点**:
- 注重文学性和艺术性
- 保持原作的风格和韵味
- 可以适当创造性翻译
- 注意修辞手法的转换

**参数**: temperature=0.5

---

### 7. 新闻风格 (news) 📰

**适用场景**: 新闻报道、时事评论等

**特点**:
- 客观、中立、准确
- 简洁明了，突出重点
- 使用新闻常用表达
- 保持时效性用语

**参数**: temperature=0.3

**示例**:
```
原文: The president announced new policies yesterday.
新闻风格: 总统昨日宣布新政策。
```

---

### 8. 口语风格 (colloquial) 💬

**适用场景**: 日常对话、聊天等

**特点**:
- 使用口语化表达
- 自然、随意、亲切
- 可以使用网络用语、流行语
- 避免过于正式的表达

**参数**: temperature=0.5

**示例**:
```
原文: Hey, what's up?
口语风格: 嘿，怎么样？/嘿，最近咋样？
```

---

### 9. 法律风格 (legal) ⚖️

**适用场景**: 法律文件、合同、条款等

**特点**:
- 使用法律专业术语
- 表达精确、严谨、无歧义
- 保持正式、庄重的语气
- 遵循法律文书规范

**参数**: temperature=0.1（最低，确保准确）

**专业术语**:
- party → 当事人/一方
- clause → 条款
- liability → 责任
- breach → 违约

## 使用方式

### 方式1: 在代码中指定

```python
from src.agents.pipeline import TranslationPipeline

pipeline = TranslationPipeline(
    planner_model=...,
    translator_a_model=...,
    translator_b_model=...,
    checker_model=...,
    stylist_model=...,
    aggregator_model=...,
    style="academic"  # 指定风格
)

result = await pipeline.translate(text, source_lang="en", target_lang="zh")
```

### 方式2: 动态切换风格

```python
pipeline = TranslationPipeline(...)

# 使用学术风格
result1 = await pipeline.translate(text, style="academic")

# 切换到商务风格
result2 = await pipeline.translate(text, style="business")
```

### 方式3: 测试不同风格

```bash
python test_different_styles.py
```

## 配置文件

### config/styles.yaml

每种风格包含：
- `name`: 风格名称
- `description`: 风格描述
- `guidelines`: 指导原则（列表）
- `temperature`: 温度参数
- `terminology`: 专业术语表（可选）
- `examples`: 示例（可选）

**示例配置**:
```yaml
styles:
  academic:
    name: "学术风格"
    description: "适用于学术论文、研究报告等"
    guidelines:
      - "使用学术规范用语"
      - "专业术语准确，统一"
      - "表达严谨，逻辑清晰"
    temperature: 0.2
    terminology:
      research: "研究"
      hypothesis: "假设"
```

## 自定义风格

### 添加新风格

1. 编辑 `config/styles.yaml`
2. 添加新的风格配置：

```yaml
styles:
  custom_style:
    name: "自定义风格"
    description: "你的风格描述"
    guidelines:
      - "指导原则1"
      - "指导原则2"
    temperature: 0.3
    terminology:
      term1: "翻译1"
      term2: "翻译2"
```

3. 使用新风格：

```python
pipeline = TranslationPipeline(..., style="custom_style")
```

## 风格选择建议

| 内容类型 | 推荐风格 |
|---------|---------|
| 技术内容 | technical |
| 商业文档 | business |
| 学术论文 | academic |
| 日常对话 | colloquial / native |
| 新闻文章 | news |
| 法律文件 | legal |
| 文学作品 | literary |
| 一般内容 | general |

## 风格对比示例

**原文**: The company announced its quarterly earnings yesterday.

| 风格 | 翻译结果 |
|-----|---------|
| general | 该公司昨天公布了季度收益。 |
| business | 该公司于昨日发布季度财务业绩公告。 |
| native | 这家公司昨天公布了这个季度的业绩。 |
| news | 该公司昨日宣布季度业绩。 |
