# 项目结构说明

## 项目概述

**多模型协作翻译系统 V3.0** - 一个基于大语言模型的多阶段、多模型协作翻译系统，支持多种语言翻译成中文。

## 核心模块说明

### 1. 翻译工作流 (src/agents/)

#### Pipeline (pipeline.py)
- **功能**: 翻译工作流编排器，协调6个阶段的Agent
- **主要方法**: `translate()` - 执行完整翻译流程
- **输入**: 待翻译文本、源语言、目标语言、术语表、风格
- **输出**: `FinalTranslation` - 包含最终翻译和可解释性报告

#### 六个阶段Agent

1. **Planner (planner.py)**
   - 任务规划：语言检测、文本拆分、识别复杂段落
   - 使用模型：GPT-4

2. **Translator-A (translator_a.py)**
   - 主翻译：执行初步翻译
   - 使用模型：Gemini
   - 输出：翻译草稿 + 自检报告

3. **Translator-B (translator_b.py)**
   - 对照翻译：提供对比翻译版本
   - 使用模型：Qwen/DeepSeek
   - 输出：翻译草稿 + 自检报告

4. **Checker (checker.py)**
   - 质量检查：一致性检查、MQM评分
   - 使用模型：GPT-4
   - 输出：检查报告（一致/冲突段落、质量评分）

5. **Stylist (stylist.py)**
   - 风格化：术语统一、风格统一
   - 使用模型：Qwen/DeepSeek
   - 输出：风格化文本 + 变更记录

6. **Aggregator (aggregator.py)**
   - 最终整合：生成最佳翻译、可解释性报告
   - 使用模型：GPT-4
   - 输出：最终翻译 + 完整报告

### 2. 模型接口 (src/models/)

所有模型都继承自 `BaseModel`，实现统一的接口：
- `translate(request: TranslationRequest) -> TranslationResult`
- `validate_config() -> bool`

支持的模型：
- **OpenAI**: GPT-4, GPT-3.5（通过OpenRouter）
- **Gemini**: gemini-2.5-flash, gemini-pro（通过OpenRouter）
- **Qwen**: qwen-turbo, qwen-plus（通过DashScope）
- **Claude**: claude-3-opus（通过OpenRouter）
- **DeepSeek**: deepseek-chat（通过OpenRouter）

### 3. 配置系统 (config/)

#### config.yaml
- 应用配置：名称、版本、日志级别
- 策略配置：voting/weighted/confidence
- 默认翻译参数：温度、最大token数
- 默认风格和术语表

#### models.yaml
- 各模型的启用状态
- API密钥环境变量名
- 模型参数（temperature, max_tokens等）
- 模型权重（用于加权策略）

#### styles.yaml
- 9种翻译风格的定义和提示词
- 风格：general, native, business, academic, technical, literary, news, colloquial, legal

### 4. 评估系统 (src/evaluation/ + src/utils/)

**V3.0更新**: 评估功能已部分分离到独立库，但保留本地评估能力。

- **评估指标**: BLEU, COMET, BLEURT, BERTScore, MQM, ChrF
- **评估模式**: 
  - API模式：通过HTTP API调用评估服务
  - 本地模式：使用共享评估库
- **评估服务**: `EvaluationService` 统一接口

### 5. 工具模块 (src/utils/)

- **logger.py**: 统一的日志系统（基于loguru）
- **model_factory.py**: 从配置创建模型实例
- **validator.py**: 数据验证
- **evaluator_env.py**: 评估器环境管理
- **eval_api_client.py**: 评估API客户端
- **evaluation_service.py**: 评估服务封装

## 工作流程

```
用户输入文本
    ↓
1. Planner: 语言检测 + 任务拆分
    ↓
2. Translator-A: 主翻译（Gemini）
3. Translator-B: 对照翻译（Qwen）  [并行]
    ↓
4. Checker: 一致性检查 + MQM评分
    ↓
5. Stylist: 术语统一 + 风格统一
    ↓
6. Aggregator: 最终整合 + 生成报告
    ↓
最终翻译结果 + 可解释性报告
```

## 数据流

```
文本输入
  → TaskPlan (任务计划)
  → TranslationDraft[] (翻译草稿列表)
    ├─ Translator-A Draft
    └─ Translator-B Draft
  → CheckerReport (检查报告)
  → StylistResult (风格化结果)
  → FinalTranslation (最终结果)
    ├─ translated_text
    └─ explainability_report
```

## 主要功能

1. **多阶段翻译**: 6个专业阶段，每个阶段由专门Agent负责
2. **多模型协作**: 充分发挥不同模型的优势
3. **质量保证**: 双重翻译 + 一致性检查 + MQM评分
4. **风格定制**: 支持9种翻译风格
5. **术语管理**: 支持自定义术语表
6. **可解释性**: 详细的修改记录和质量改进报告
7. **批量处理**: 支持批量翻译和评估
8. **评估集成**: 支持多种评估指标

## 使用方式

### 1. 命令行脚本
- `quick_start.py`: 快速开始
- `quick_test.py`: 快速测试
- `evaluate_flores_batch.py`: 批量评估

### 2. Python API
```python
from src.agents.pipeline import TranslationPipeline
# ... 创建pipeline并调用translate()
```

### 3. 配置文件
- 通过 `config/` 目录下的YAML文件配置
- 通过 `.env` 文件配置API密钥

## 技术栈

- **Python**: 3.8+
- **异步编程**: asyncio
- **配置管理**: PyYAML, python-dotenv
- **日志**: loguru
- **HTTP客户端**: requests (用于评估API)
- **模型API**: OpenAI, Google Generative AI, DashScope, OpenRouter

## 扩展性

- **添加新模型**: 继承 `BaseModel` 并实现接口
- **添加新Agent**: 在 `src/agents/` 下创建新模块
- **添加新策略**: 在 `src/agents/strategies/` 下实现
- **添加新风格**: 在 `config/styles.yaml` 中配置
