# 翻译系统并发支持说明

## 当前并发能力

### ✅ 已支持的并发

1. **多个翻译任务并发执行**
   - FastAPI 是异步框架，支持并发处理多个请求
   - `TaskManager` 使用 `asyncio.create_task()` 为每个任务创建独立的异步任务
   - 多个用户可以同时提交翻译任务，系统会并发处理

2. **异步API端点**
   - 所有API端点都使用 `async def`，支持异步处理
   - WebSocket连接支持多个客户端同时连接

3. **任务隔离**
   - 每个任务使用独立的 `TranslationPipeline` 实例
   - 不同任务的API_KEY不会混用
   - 任务之间互不影响

### ❌ 当前限制

1. **单个任务内部顺序执行**
   - 翻译管道的6个阶段（Planner → Translator-A → Translator-B → Checker → Stylist → Aggregator）必须顺序执行
   - 这是因为每个阶段依赖前一个阶段的输出
   - 这是设计上的要求，不是技术限制

2. **段落处理顺序执行**
   - 如果一个任务包含多个段落，段落之间是顺序处理的
   - 当前实现中，段落处理是串行的（`for idx, task_item in enumerate(task_plan.tasks)`）

## 并发架构

```
用户请求1 ──┐
用户请求2 ──┼──> FastAPI (异步) ──> TaskManager ──> 任务1 (异步执行)
用户请求3 ──┘                                    └──> 任务2 (异步执行)
                                                      └──> 任务3 (异步执行)
```

每个任务内部：
```
任务1: Planner → Translator-A → Translator-B → Checker → Stylist → Aggregator
任务2: Planner → Translator-A → Translator-B → Checker → Stylist → Aggregator
任务3: Planner → Translator-A → Translator-B → Checker → Stylist → Aggregator
```

## 性能特点

### 优势
- ✅ 多个任务可以同时运行，充分利用服务器资源
- ✅ 异步I/O，在等待API响应时不会阻塞其他任务
- ✅ 任务隔离，一个任务失败不影响其他任务

### 限制
- ⚠️ 单个任务内部是顺序的，无法并行化
- ⚠️ 段落处理是串行的，如果段落很多会比较慢

- 5个任务应该几乎同时开始执行
- 每个任务独立完成，互不干扰
- 总执行时间 ≈ 单个任务时间（而不是5倍）

## 优化建议

### 1. 段落并发处理（推荐）

**当前实现**：段落顺序处理
```python
for idx, task_item in enumerate(task_plan.tasks):
    # 顺序处理每个段落
    draft_a = await pipeline.translator_a.translate(...)
    draft_b = await pipeline.translator_b.translate(...)
    # ...
```

**优化方案**：段落并发处理
```python
# 并发处理所有段落
tasks = [
    process_segment(segment, pipeline, task_plan)
    for segment in task_plan.tasks
]
results = await asyncio.gather(*tasks)
```

**效果**：
- 如果任务有10个段落，理论上可以快10倍
- 但需要注意API限流和资源消耗

### 2. 使用Gunicorn多进程

**当前**：单进程运行
```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

**优化**：多进程运行
```bash
gunicorn app.main:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:8000
```

**效果**：
- 4个worker进程，可以同时处理更多请求
- 适合CPU密集型任务

### 3. 连接池优化

**当前**：每个模型可能创建新的HTTP连接

**优化**：使用连接池
```python
import httpx

async with httpx.AsyncClient() as client:
    # 复用连接
    response = await client.post(...)
```

## 实际并发能力

### 理论值
- **FastAPI**: 可以处理数千个并发连接
- **asyncio**: 可以同时运行数千个协程
- **实际限制**: 主要受限于：
  - API提供商的限流（如每分钟请求数）
  - 服务器内存和CPU
  - 网络带宽

### 建议配置

**开发环境**：
- 单进程：`uvicorn app.main:app --reload`
- 适合：1-10个并发用户

**生产环境**：
- 多进程：`gunicorn -w 4 -k uvicorn.workers.UvicornWorker`
- 适合：10-100个并发用户

**高并发环境**：
- 多进程 + 负载均衡（Nginx）
- 适合：100+ 并发用户

## 监控并发

### 查看运行中的任务

```python
# 在TaskManager中添加方法
def get_running_tasks_count(self) -> int:
    return len(self.running_tasks)

def get_all_tasks_count(self) -> int:
    return len(self.tasks)
```

### 日志监控

查看后端日志，应该能看到：
```
[INFO] 开始执行翻译任务 [Task ID: xxx-1]
[INFO] 开始执行翻译任务 [Task ID: xxx-2]
[INFO] 开始执行翻译任务 [Task ID: xxx-3]
```

多个任务同时执行时，日志会交错显示。

## 总结

✅ **当前系统支持并发**：
- 多个翻译任务可以同时执行
- FastAPI异步框架支持高并发
- 任务之间完全隔离

⚠️ **限制**：
- 单个任务内部必须顺序执行（设计要求）
- 段落处理是串行的（可优化）

🚀 **优化方向**：
- 段落并发处理（最大收益）
- 多进程部署（提高吞吐量）
- 连接池优化（减少延迟）
