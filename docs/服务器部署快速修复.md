# 服务器部署 CORS 问题快速修复

## 问题

前端运行在 `http://47.254.82.238:8088`，后端运行在 `localhost:8000`，出现CORS错误。

## 快速修复（3步）

### 步骤1: 修改后端 `.env` 文件

在服务器上编辑 `web/backend/.env` 文件，添加：

```env
ALLOWED_ORIGINS=http://47.254.82.238:8088
```

**如果前端可能使用多个端口，用逗号分隔：**

```env
ALLOWED_ORIGINS=http://47.254.82.238:8088,http://47.254.82.238:3000,http://47.254.82.238:5173
```

### 步骤2: 确保后端绑定到 0.0.0.0

重启后端服务，确保使用 `--host 0.0.0.0`：

```bash
cd ~/agent/translator_online/Translator_online/web/backend
source venv/bin/activate
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

**重要**：`--host 0.0.0.0` 必须，否则外部无法访问。

### 步骤3: 检查防火墙

确保服务器防火墙开放了8000端口：

```bash
# Ubuntu/Debian
sudo ufw allow 8000/tcp

# 或 CentOS/RHEL
sudo firewall-cmd --permanent --add-port=8000/tcp
sudo firewall-cmd --reload
```

### 步骤4: 刷新前端页面

在浏览器中强制刷新（Ctrl+F5 或 Cmd+Shift+R），清除缓存。

## 验证

### 1. 测试后端是否可访问

```bash
# 在服务器上测试
curl http://localhost:8000/health

# 应该返回: {"status":"ok","version":"1.0.0"}
```

### 2. 从外部测试

在浏览器中访问：`http://47.254.82.238:8000/health`

应该能看到JSON响应。

### 3. 测试前端

刷新前端页面，点击"开始翻译"，应该不再有CORS错误。

## 如果还有问题

### 检查后端日志

查看后端启动日志，确认：
- ✅ 配置验证通过
- 🚀 服务启动成功

### 检查CORS配置是否生效

在后端日志中应该能看到允许的源列表。

### 检查前端API地址

打开浏览器开发者工具（F12），查看Network标签，确认请求的URL是 `http://47.254.82.238:8000/api/...` 而不是 `http://localhost:8000/api/...`

## 完整配置示例

### 后端 `.env` 文件

```env
# API密钥
DEEPSEEK_API_KEY=your-key-here
QWEN_API_KEY=your-key-here
DOUBAO_API_KEY=your-key-here

# CORS配置（允许的前端域名）
ALLOWED_ORIGINS=http://47.254.82.238:8088,http://47.254.82.238:3000

# 环境
ENV=production

# 可选：Token认证
SHARED_TOKEN=your-secret-token
```

### 后端启动命令

```bash
cd web/backend
source venv/bin/activate
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

**生产环境建议去掉 `--reload`**，使用：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000 --workers 4
```

或使用 gunicorn：

```bash
pip install gunicorn
gunicorn app.main:app -w 4 -k uvicorn.workers.UvicornWorker --bind 0.0.0.0:8000
```
